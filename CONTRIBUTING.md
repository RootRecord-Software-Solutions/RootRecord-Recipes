# Contributing to RootRecord Recipes

Thank you for helping make the cookbook useful and welcoming.

## Publication review is required

Every new recipe or public-facing revision must be reviewed by an authorized RootRecord maintainer **before it is published or merged**. A pull request, automated test, or generated draft is not by itself approval to publish. Repository maintainers should configure branch protection or rulesets to enforce review where available.

### Review checklist

- [ ] The recipe is clear, factual, and safe to follow; cooking guidance is verified.
- [ ] Its title, introductory text, and notes use professional, public-facing language.
- [ ] It contains no profanity, private conversation excerpts, personal routines, private photographs, internal logs, or unapproved personal/location details.
- [ ] It does not contain passwords, tokens, internal endpoints, customer records, or private infrastructure information.
- [ ] Ingredients and quantities are not presented as confirmed if they were only estimated or are unknown.
- [ ] Public links work, and the root README points only to recipes present in the current repository.
- [ ] Contributors or recipe origins are credited only with permission.
- [ ] A maintainer has examined the **entire public diff**, including file paths and metadata, and approved publication.

## Writing a recipe

Use a descriptive title, ingredients, step-by-step instructions, optional serving suggestions, and cooking tips. Write for a reader who has not seen any original conversations or drafting notes.

Keep recipe-specific working notes in a private workspace. Publish a clean derivative instead of pasting a transcript into this public repository.

## Important note about history

**Deleting text from a public branch does not erase it from Git history.** Contact the repository owner if material was published without approval so that exposure and any separate history-remediation decision can be assessed.
